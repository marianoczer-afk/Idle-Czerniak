# Argentum Idle Online — development

Read `docs/ARQUITECTURA.md` first, then only the relevant system files. `DESARROLLO.md` is the current workflow; older release notes describe history, not the active implementation.

- Edit `src/`, not generated root `index.html`. Build with `npm run build`; commit source and generated distribution together only when gameplay sources change.
- Preserve the explicit order in `src/blocks.json` and placement in `src/template.html`. Scripts are classic globals, not independent ES modules. Includes inject catalogues in place.
- Do not append another version wrapper to solve a routine issue. Find the active implementation and its captured predecessors first. Use `npm run architecture:inventory` (the saved audit inventory predates the renderer consolidation); do not load its entire JSON by default. A repeated function name is not evidence that its predecessors can be deleted.
- Normal logic/CSS changes need no image generation, `art:prepare`, `assets:optimize`, art inventory export, gallery regeneration, release ZIP or screenshots of every screen. Run those only for relevant asset/layout changes or an explicitly requested release. Keep all original art.
- Use the architecture map to select system paths, then search symbols with `rg -n` and read bounded matching sections. Expand to callers, captured aliases, catalogues and load order when dependencies require it; avoid whole-file reads or repository-wide searches as the default.
- Treat the architecture map as a starting point, not a complete dependency graph. Before renaming or removing shared symbols, or changing save schemas, catalogues or load order, broaden searches across relevant source, template, build and test paths; inspect indirect references where applicable. Do not infer absence of dependencies from scoped search results alone.
- Default search excludes the generated HTML, binary art and archived downloads via `.rgignore`. Inspect a specific excluded file explicitly or use `rg --no-ignore` when needed. Do not feed base64 images or historic source dumps into context for logic changes.
- For code changes, start with `npm run test:fast` (no browser); documentation-only changes need diff/content checks instead. For capture/persistence/migration changes also run `npm run test:smoke`. Add the relevant named browser cases. Use `npm run test:render` for page/HUD refactors and the full current fishing suite for broad Pesca changes. Run `npm run test:full` for cross-system/final integration validation; historical version/art/controller expectations have been brought up to date. Report every executed result and any limit; never describe the full suite as green because a subset passes.
- Group related edits before final validation; run intermediate checks when useful. Reuse passing results within the current task only when the executed command, checked working-tree state (including uncommitted edits and generated inputs), relevant dependencies/configuration and test conditions remain unchanged. For captures, also preserve viewport and fixture/save state. Record the command, result and validated state; if relevance is uncertain, rerun the affected check. Never report a reused result as a new execution or a subset as full validation.
- Record observable start/end timestamps and elapsed wall time for environment/update, source inspection, edits, build/tests, captures/art/packaging and delivery, including commands and execution counts. State the observation window and distinguish initial setup from incremental updates. Report total observed task time without double-counting overlapping events; leave unobservable intervals UNATTRIBUTED and unavailable measurements NOT MEASURED. Do not infer reasoning time from gaps between tool calls. Keep evidence outside tracked files and summarize it in the final response.
- Screenshots are needed for visual changes, at desktop/mobile widths. Avoid recapturing unrelated screens. Keep verification output separate from player data. Use isolated Chromium contexts, never a player's profile.
- `npm run build:profile` measures build stages without changing output. `test:assets` requires Pillow and tests optimizer caching in temporary fixtures. Node build does not need Pillow.
- Preserve v7 unknown fields, inventory, historical IDs, claims and records. No balance, quest, fish, rod or mechanic changes without task scope. Keep the fixed bottom HUD at 118px unless explicitly authorized otherwise.
- Do not commit/push directly to `main` without explicit approval for the current task. Work on a review branch; never merge a PR automatically.
- Keep only the current playable release ZIP in `descargas/`; remove superseded release ZIPs from the active tree when publishing a new stable version. Do not commit historical code dumps or handoff transcripts.
- Temporary screenshots and generated galleries/inventories are ignored by default. If the user explicitly needs visual evidence checked into Git, select and force-add only the requested files. Do not automatically add all screenshots.
